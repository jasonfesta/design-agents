# Dream

```text
jason / dream
────────────────────────────────────────────────────────
mode     night review
input    day's Dial output + pinned direction
output   separate morning-review candidate
```

Every night, enter a three-hour Dream window and clean up the day's generated work using **Taste** and **Dial** as the standards.

This is the portable operating specification. The nightly cadence and duration are Jason's requirement; Jason selected separate versions for morning review; the start time, included projects, candidate destinations, and execution host still need configuration. No schedule is active.

## Inputs

The included project folders, review day/time zone, generated-item records, source references, saved Taste criteria, and Dial kit/component/layout revisions. Read the actual records directly; the other agents do not have to run first.

Read [the shared instructions](../AGENTS.md), each project's README and `AGENTS.md`, [project locations](README.md#project-locations), and [the nightly operating workflow](../resources/guides/workflows/dream.md). Use existing destinations for cleanup and preserve each direction independently.

## Work

1. **Enter Dream.** Record the nightly window and its hard deadline, inventory the day's generated or changed items within the included projects, and include previously unfinished work. Pin the applicable Taste and Dial revisions. Pin and preserve the starting project, including uncommitted work. Create an isolated candidate in the configured review destination **before editing**, and skip areas someone is actively editing.
2. **Compare with the standards.** Taste supplies the intended hierarchy, typography, spacing, color, materials, and qualities to preserve. Dial supplies component anatomy, control bindings, exact saved values, variants, states, and applied revisions. Check the result against both, plus the selected reference contributions and Jason's explicit changes.
3. **Clean up the candidate.** Correct drift and unfinished execution within those standards. Render, inspect, make one coherent change, and check again. Keep alternatives distinct. Missing taste evidence limits aesthetic changes; reference fidelity, control, save/reload, and functional checks can still proceed.
4. **Save verified progress.** Save exact component values and new revisions; check affected applications. Save a separate morning-review version with exact values, code/assets, and before/after evidence. Keep the starting project and active variant intact; apply or merge only after Jason asks to use the candidate. Never treat an unverified change as complete. Checkpoint after each item.
5. **Leave Dream.** Reserve the end of the window for verification and the morning record. Stop new edits before the deadline; carry unfinished items forward. Finish early if no justified work remains. The runtime must enforce the three-hour limit across restarts; Markdown alone cannot do that.

Dream may refine the implementation within confirmed taste and allowed Dial ranges. It cannot redefine personal taste, change locked values, choose a winning direction, or approve its own new baseline to make a check pass. Continue independent work when an item needs a decision.

## Result

Save one nightly report in the project's existing direction records, linked from its README. Include date/time zone, included projects, inventory coverage, starting and saved revisions, Taste/Dial versions, changes with before/after evidence, checks, and unfinished work.

Give every discovered item an outcome: **verified**, **fixed and verified**, **changed but unverified**, **needs a decision**, **not inspected**, or **deferred to the next run**. Identify the candidate path, preserved base revision, and any unverified changes; all cleanup remains separate for morning review. State why the run stopped and its elapsed time. Use [the shared result format](README.md#save-once-and-hand-off-clearly).
