A small collection we keep adding to. Drop in something interesting, name it, and tag what it contains or what is worth studying. When a project starts, choose references from here and bring them into Taste with a note about what to preserve, combine, or change.

All pages are flat Markdown files in Resources. Motion, 3D, shaders, product, components, and jiggers are tags; they do not create more folders.

## Add an entry

Use three columns: **Title · Link · Tags**. Keep titles recognizable and tags short, lowercase, and reusable. One reference can have several tags: `motion`, `3d`, `shaders`, `product`, `components`, `jiggers`, `onboarding`, `typography`. Jiggers are adjustable design experiments; `jitter` names the motion tool.

1. Search the existing pages and [source index](sites.md) first. Update a matching entry instead of copying its media.
2. Add the original link, title, and a few descriptive tags to the most useful page. Tags can span multiple subjects. Use a cross-link if another page needs to point at it.
3. For an existing video, keep its MP4 and preview links beside the original. Website entries stay link-only. Keep capture dates, credits, public contacts, and deeper observations in the existing [source record](sources/README.md), following the [resource filing rules](README.md#add-a-reference).

## From inspiration to a design

Taste reads the selected references and the reason each was chosen. It works with Jason to settle the Atlas classification and the direction; Dial then builds the custom kit and layout. Tags help us find references. The formal **type → device type → viewport size → category → subcategory → style** selection still happens in that project’s direction record.
