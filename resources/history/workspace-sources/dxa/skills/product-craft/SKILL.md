# Product craft

Define the audience, primary task, current constraint, and artifact needed. For Silicon Valley product work, favor something a small team can inspect, test, and revise quickly.

Use existing product context and real content. Explore materially different approaches only when the decision is unresolved; explain differences in task flow and tradeoffs rather than decoration.

Design the critical path and relevant edge states. For agent products, make intent, progress, correction, permission boundaries, interruption, and recovery understandable. Distinguish simulated actions from implemented behavior.

Build with the chosen design system and tools. Evaluate the result against task completion, hierarchy, language, accessibility, responsiveness, and implementation effort. Visual novelty is not a substitute for those criteria.

Deliver the reviewable artifact and the specific decisions or limitations that matter for the next iteration. A demo should show what the product currently does and label proposed behavior.
