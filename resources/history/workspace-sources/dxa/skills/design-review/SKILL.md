# Design review

Identify the artifact, audience, and primary task. Use direct inspection of the running interface when available; state when the review is limited to screenshots or static designs.

Complete the main task. Inspect relevant loading, empty, error, success, and focus states; narrow layouts; long content; contrast; and motion. Choose checks that fit the artifact.

Tie each finding to a location, trigger, evidence, and user consequence. Separate defects from brand-dependent preferences. Prioritize blocked tasks and lost work before cosmetic polish.

For each actionable issue, suggest a concrete fix and a verification step. Make changes only when the user requested implementation; a review request alone should produce findings.

After authorized fixes, repeat the affected task. Report what passed, what remains, and any check that could not be performed. Avoid describing a screenshot-only review as a complete accessibility or behavioral audit.
