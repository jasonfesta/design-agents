# Contribute to Design xAgents

Share tools and examples that help designers build products with agents.

## Add a resource

Open a pull request against the relevant [agent](resources/agents.md), [MCP](resources/mcps.md), or [skill](resources/skills.md) directory.

Include:

- The resource name, type, creator, and canonical source.
- A short, original description of the design task and output.
- Setup documentation, supported environment, and account or payment requirements.
- Whether the integration is official or community maintained.
- What you reviewed or tested, the date, and any important limitation.
- The upstream license when stated; otherwise leave it unconfirmed and link to the source.
- An event or demo link only when the connection is documented.

Use the [evidence labels](resources/README.md). A successful build is a setup check, not a completed design workflow. A repository's star count is not evidence of quality.

Prefer useful additions and distinct alternatives. Link to upstream skills instead of copying their instructions. Disclose when you created or maintain a submission.

## Add an event or demo

Add a page under `events/` and link it from the event index. Include a public event source, date, city, presenter profiles, and available materials. Keep affiliations tied to the date of the source.

For a workflow test, record the task, environment, versions where known, output, inspection method, and limits. Share only artifacts intended for public distribution.

## Writing

Use **Design xAgents** and **DxA**. Describe what a designer can do with a resource in plain language. Preserve the spelling of external product names.

Keep claims specific. State when information comes from documentation rather than hands-on use.

## Before submitting

Check relative links and image paths. For skill changes, confirm the required name and description frontmatter, standalone instructions, and upstream links. Use the local discovery command in the [installation guide](agents/README.md) to check that the installer recognizes the skills.

Record meaningful additions and corrections in [Updates](resources/updates.md). Keep website changes separate unless they are part of the contribution.
