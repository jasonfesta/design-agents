## Carry or add resources

Copy the `resources/` folder into the receiving workspace, or supply its relevant Markdown files to the assistant. Keep source URLs, authors, dates, attribution, inspection status, and original labels with each record. Preserve the original license file included with imported research. Agent and tool links outside this folder are contextual references; bringing the resource documents does not install those capabilities.

The Markdown records are the maintained resource collection. Retained JSON files are historical source evidence, not a second editable catalogue.

For a new resource, create or update one Markdown record containing its name and stable ID, source URL, author, capture date, what it provides, intended use, inspection status, and relevant evidence. Link related records. Preserve differing notes when merging an existing resource instead of overwriting them by filename.

Atlas classifies these resources. Taste annotates and interprets them. Dial uses selected references. Dream revisits them. Setup handles carrying them into the destination.

For a design-environment setup, copy applicable Markdown content beneath each type at its supported viewport/category/style scope. Preserve source identity, revision, and attribution in each copy; this folder remains the master resource collection. [Setup](../instructions/SETUP.md#copy-and-refresh-rules) defines source-to-destination receipts and preservation of local edits. Unclassified resources stay here until Atlas can place them; their presence does not establish a style match.

Source code, runtime dependencies, credentials, and installed agent skills stay outside this folder. Original JSON data and source manifests are preserved under `shared/sources/resource-data/` in the full workspace; their portable resource content is available here in Markdown. Historical snapshots retain their original claims and may contain links to their original environments.
