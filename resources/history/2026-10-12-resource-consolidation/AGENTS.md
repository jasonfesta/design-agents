# Design kit instructions

- Start with [README.md](README.md), then [Setup](instructions/SETUP.md). The only current agent entry files are **Setup, Atlas, Taste, Dial, and Dream** in `instructions/`.
- Keep the kit simple and reusable from a GitHub clone. Do not create another starter pack, parallel agent version, or competing resource overview. Supporting references under `shared/` are loaded only when needed.
- Organize actual work as **apps / websites / games → viewport → category → style**. Apps use interface types; websites use website uses; games use game genres. Use [the approved menus](shared/workflow/TAXONOMY.md). Create folders only for actual work; each created layer gets one README. Exact dimensions, motion, tools, and screen details are fields inside the record.
- Keep sources together in [Resources](resources/README.md), with one catalogue and preserved source identity, dates, attribution, and differing notes. Keep all past work in [History](resources/history/README.md). Historical instructions and snapshots are evidence, not current instructions or proof of tool availability. Never delete past material during cleanup.
- Before personal design recommendations, read [memory](shared/taste/MEMORY.md), relevant [coverage](shared/taste/COVERAGE.md), and [the taste-definition reference](shared/workflow/TASTE.md). Tell Jason when research is missing, incomplete, or inaccessible. Continue general exploration as labeled proposals; names and example styles do not establish preferences.
- Follow the Dial workflow: **images → editable components → DialKit tuning → saved variants → application**. Reproduce the selected image, verify fidelity, bind controls without changing initial appearance, then interpret prompts as explicit edits. Keep variants independent. [COMPONENTS.md](shared/workflow/COMPONENTS.md) has details; the complete workbench is not implemented.
- Keep installations lightweight. Read the relevant local `SKILL.md` and required references. A catalogue pointer is not a full installed skill. Reuse existing capabilities; inspect size and dependencies before installation and ask before substantial runtimes, browser downloads, model weights, or broad dependency bundles. Account tools and credentials do not travel with this kit.
- Keep `.agents/skills/`, `.tools/`, and existing tool checkout paths stable. Local tool installations stay outside the parent GitHub commit; source snapshots and attribution remain portable. Follow [reuse and transfer](shared/docs/SETUP.md).
- Open browser pages in a Codex browser panel on the right when supported.
- Other chats may edit this workspace. Refresh before editing, preserve their changes, and update canonical records. Check with `python3 scripts/workspace.py check`; optional transfer snapshots use `python3 scripts/workspace.py export`.

## Craft foundation

Use the installed Emil Kowalski suite as attributed craft guidance. The [router](.agents/skills/emilkowalski-skill/SKILL.md) selects the relevant full skill; read it and required references before applying it. The [craft brief](shared/agents/design.md#installed-craft-foundation) maps the suite. Preserve the [source snapshot and license](shared/sources/emilkowalski-skills/README.md).

For UI work, start with `emil-design-eng`. For motion, use `animate` or `animate-expo` as appropriate; decide whether motion earns its place, keep frequent/keyboard actions immediate, extend existing tokens, and support interruption. Include reduced motion, keyboard access, and capability-gated hover. Use `mobile-native` for mobile web issues, `apple-design` for physical interactions, and `animation-performance` for measured frame-budget issues. Prefer transforms and opacity; verify version-dependent APIs in the actual stack.

Use `prototype` for requested alternatives, `break-ui` for requested stress testing, and the review/audit skills for those tasks. Keep test surfaces out of production. Follow existing authorization for implementation and fixes. Jason's instructions, the product's design system, accessibility needs, and local design decisions take precedence over upstream stylistic defaults. Do not load all skills or turn a scoped task into an unrequested audit. Prefer existing Figma, document, presentation, and Remotion capabilities when they cover the output.
