## Naming rules

- Use an attested preferred term and a stable ID. Preserve earlier IDs when their meaning is unchanged; record spelling variants as aliases.
- State the kind of term: composition approach, historical tradition, contemporary interface style, cultural aesthetic, rendering treatment, motion technique, or tool. These groups are metadata, not more folder levels.
- Record broader, narrower, and related terms explicitly. Similar appearance does not make two terms aliases.
- Preserve the primary source menu even where it contains color, density, rendering, or intent words. Record the term’s kind and observable rules. Additional modifiers such as chrome, CRT, halftone, dark mode, bento layout, and spring timing stay in fields.
- A researched direction may combine influences. Use one primary term and explain the secondary contributions rather than inventing a universal style name from every combination.

The path remains `<type>/<device>/<width>x<height>/<category>/<subcategory>/<style>/`. A branch record defines its visual recipe, rendering, motion, tools, sources, and versions inside that sixth layer. Game art and HUD can use different recipes.

## Extended visual terms

The groups below help browsing; they are not an exclusive or universal classification. Historical movements can span several design disciplines. Contemporary UI terms can describe a surface system rather than an entire art direction. Every term still needs an actual reference and scoped rules before use.

Minimalism and flat design remain distinct. Skeuomorphism, neumorphism, and claymorphism describe different relationships to physical appearance. Bauhaus, De Stijl, Swiss Style, and Memphis retain separate historical contexts.

## Rendering and material vocabulary

Keep rendering/media terms available to designers: pixel art, voxel art, low-poly, cel shading, vector illustration, hand-drawn illustration, painterly rendering, photorealism, collage, papercraft, halftone, dithering, and risograph-inspired texture. [Games](../games/styles.md) supplies scoped definitions and evidence for its rendering/art terms. The remaining media terms require a specific source when activated. A rendering-led direction can use a name such as `pixel-art`; it must still define a complete recipe. Terms such as isometric describe projection, and bento describes layout.

Remotion, Jitter, After Effects, Rive, GSAP, and Motion are tool names. Keep them in the environment/tool field. [MOTION.md](../motion/techniques.md) defines the techniques we can name independently of an implementation.

## Match a style to a branch

Start with style unset. Record **unassessed**, **candidate match**, **supported match**, or **not a fit**, with reasons and references. Requested exploration can create a candidate style folder; it does not establish a personal preference. Apply [the taste-definition process](../guides/workflows/taste.md) before using a style as Jason's taste.

Each style record states the intended task, viewport/profile, relevant category, defining rules, exclusions, inspected references, Jason's reaction, and unsupported aspects. Use [the style README template](template.md) when creating an actual folder.

For games, the art style and interface treatment can differ. For apps, a platform design system can constrain components without defining the whole visual style. For websites, page purpose is a separate detail. Keep density, light/dark mode, color temperature, motion intensity, and words such as luxury or friendly as explicit controls or intent tags.

[Earlier shared families](../history/style-vocabulary.md) retain the previous family/treatment vocabulary for old records. New records use the type-specific menu and record aliases where needed. Selecting a menu entry alone does not create an approved baseline.
